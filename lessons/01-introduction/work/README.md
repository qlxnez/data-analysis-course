## A. Разделитель CSV

В файлах reading_example.csv (6 записей) и decisions.csv (6830 записей) в качестве разделителя полей используется точка с запятой (;). Это важно для корректного парсинга: при загрузке данных нужно явно указать этот разделитель, иначе столбцы не разделятся и таблица будет искажена. Маленький файл удобен для визуальной проверки структуры и разделителя, большой — для расчётов по реальной выборке.

## B. Частичное чтение

Параметр nrows задаёт количество строк, которые реально считываются из файла: например, при nrows=3 в память попадает ровно 3 строки, что снижает нагрузку на ресурсы.
Параметр usecols позволяет загружать только выбранные колонки (например, ["action_taken", "income"]), формируя таблицу строго из нужных полей.
На файле reading_example.csv (6 записей) это наглядно демонстрирует, как можно быстро проверить структуру данных, не загружая лишние строки и столбцы.
Ключевое отличие от .head() состоит в моменте ограничения: nrows сокращает объём данных на этапе чтения, тогда как .head() лишь отображает часть уже полностью загруженного набора.
Такой подход особенно важен при работе с большим файлом decisions.csv (6830 записей), поскольку позволяет эффективно управлять объёмом загружаемых данных и экономить вычислительные ресурсы.


## C. Выбор столбцов

При выборе одного столбца (example["action_taken"]) возвращается объект Series — это одномерный массив (как колонка).
При выборе в квадратных скобках списка (example[["action_taken"]]) получается DataFrame — табличный формат даже из одной колонки.
Просмотр столбцов не меняет исходную таблицу example: данные остаются без изменений.
В столбце loan_amount указаны суммы кредитов — единица измерения: доллары США ($).


## D. Маленький пример

Одобрениями считаются записи, где action_taken равен 1 или 2. Доля одобрений (approval_rate) рассчитывается как отношение количества таких записей к общему числу строк в выборке.

Выдачами считаются только записи со значением action_taken == 1, поэтому доля выдач (origination_rate) определяется отдельно — через отношение числа таких записей к общему количеству строк.

В примере с файлом reading_example.csv знаменателем в обоих случаях выступает общее число записей — 6 шт. Это позволяет на малом объёме наглядно проверить логику расчётов перед применением к полному набору данных.

## F. Проверки

Проверено, что количество одобрений и отказов в сумме равно общему числу записей. Также проверено, что количество выданных кредитов не превышает количество одобрений, а рассчитанные доли находятся в диапазоне от 0 до 1. Эти проверки помогают обнаружить ошибки в подсчёте, неверные условия фильтрации и некорректные результаты вычислений.

Пропущенный доход не влияет на эти показатели, поскольку они рассчитываются по столбцу action_taken, а не по income. Если не удалять строки с пропущенным доходом, знаменателем остаётся полное количество записей — 6830.
## G. Исправление отчёта
В ноутбуке переменная approval_rate считалась как full_outcomes.eq(1).sum() / full_n. Это условие «только код 1», то есть доля выдач (87,20 %), а название обещает долю одобрений (коды 1 и 2, 89,88 %). Два исправления:

Название сохранено — условие исправлено: approval_rate = full_outcomes.isin([1, 2]).sum() / full_n → 89,88 %.
Условие сохранено — название исправлено: origination_rate = full_outcomes.eq(1).sum() / full_n → 87,20 %.
Название показателя должно совпадать с условием отбора и знаменателем: число несёт смысл только вместе с определением. Если назвать долю выдач «долей одобрений», читатель получит неверный вывод (занизит одобрения на 2,68 п.п.).

## Вывод

В работе были проанализированы данные HMDA за 2023 год по округу Колумбия (Вашингтон, США). Для основного набора из 6830 записей доля одобрений составила 89,88%, а доля выданных кредитов — 87,20%. Показатели рассчитаны по значениям action_taken: одобрения включают коды 1 и 2, а выдачи — только код 1. Полученные результаты относятся к записям основного набора данных, а не ко всем ипотечным заявкам в США.
